# 模型孵化与改造

这份文档解决一个问题：当内置目录里没有合适的模型时，如何从公开仓库筛出一个值得"孵化"的小模型，审查它的许可能否安全商用，并判断用哪条本地化改造路径把它变成可用工具。

## 一、什么叫"孵化"

"孵化"指把一个公开仓库里的开源模型，经过审查、评估、必要改造后，纳入自己的可用模型清单并部署运行。它区别于直接拉取成熟模型：孵化对象通常是**小众、专用、新发布**的模型，需要你先替它做合规和价值判断。

适用时机：内置目录的能力覆盖不了你的场景（如特定行业术语、特殊格式输出、某种编程语言特化），而你希望用一个轻量、可控、可商用的模型来解决。

## 二、从公开仓库找候选的流程

1. **定检索词**：按"任务 + 规模 + 语言"组合关键词，如 `coder 7b`、`中文 法律 4b`、`function calling 8b`。
2. **公开检索**：用工具按下载量排序拉取候选列表，先看许可和活跃度，不急着下载。
3. **逐个体检**：对入围者查许可证、体积、下载量、更新时间、权重格式（见下一节）。
4. **小范围试跑**：只下载最小量化版本跑几个真实任务，验证它真的对口，再决定是否长期孵化。
5. **纳入清单**：通过后登记来源、许可、基线信息，按正常部署流程接入。

GitHub 上的模型多附带训练代码与数据集说明，适合做深度改造；Hugging Face 上的模型权重生态更全、量化版本更多，适合快速试跑。两者都可作为来源。

## 三、许可证审查：能不能商用是生死线

许可证是孵化的**第一硬门槛**，比能力更重要。能力再强，许可不允许商用就不能进生产。

| 许可类型 | 商用 | 修改/微调 | 再发布 | 备注 |
|---|---|---|---|---|
| Apache-2.0 | ✓ | ✓ | ✓ | 需保留版权与许可声明，有专利授权条款，最省心 |
| MIT | ✓ | ✓ | ✓ | 极度宽松，保留许可声明即可 |
| BSD-2/3-Clause | ✓ | ✓ | ✓ | 宽松，保留声明即可 |
| MPL-2.0 | ✓ | ✓ | ✓ | 文件级 copyleft，修改的文件需开源，注意隔离 |
| LGPL | ✓（有条件） | ✓ | ✓ | 动态链接一般可商用，静态链接有开源义务，需谨慎 |
| GPL / AGPL | 有条件 | ✓ | ✓ | 强 copyleft，衍生作品须同许可开源；AGPL 对网络服务也触发，**商用高风险，默认不收** |
| CC-BY-NC / NC | ✗ | — | — | 明确禁止商用，一律不收 |
| 自定义/研究用途 | 视条款 | — | — | 常见于"仅限研究"，默认不收，除非逐条确认 |

审查红线：

- **有 MAU（月活）限制、营收上限、或"非商业用途"条款的，一律不进生产。**
- 许可信息缺失、只有 README 口头声称"可商用"的，不采信——以仓库 LICENSE 文件或 cardData 的 license 字段为准。
- 模型权重许可与训练数据/基础模型许可可能不一致，**两者都要看**（见第六节）。

## 四、评估一个模型值不值得孵化

过完许可关，再用下面这张表判断"值不值得投入时间"：

| 指标 | 看什么 | 好的信号 | 危险信号 |
|---|---|---|---|
| 体积 | Q4 量化后大小 | 与硬件匹配（见硬件分档） | 远超可用内存，改造也跑不动 |
| 下载量 | 近期下载趋势 | 有一定社区使用量 | 个位数下载，可能无人维护 |
| 更新时间 | 最近一次提交/发布 | 近几个月活跃 | 一年以上未更新，可能已废弃 |
| 格式 | 是否有 GGUF + Safetensors | 两者都有，开箱可跑可改 | 只有.bin/pickle，加载有安全风险 |
| 数据集质量 | 训练数据说明是否透明 | 有清晰来源、许可、清洗说明 | 数据来源不明，可能含受限内容 |
| 底座许可 | 基础模型与数据许可 | 均可商用 | 底座是 NC/研究许可，衍生也受限 |

**格式要点**：GGUF 是本地推理友好格式（Ollama/llama.cpp 直接吃）；Safetensors 是安全训练格式（不含可执行代码，加载不触发 pickle 反序列化）。两者兼备的模型，既能快速部署，又留有微调空间。只提供 `.bin` 的模型，加载时可能执行任意代码，谨慎对待。

## 五、本地化改造的三条路径

从轻到重，按需选择，优先用轻的：

| 路径 | 做什么 | 成本 | 适用 |
|---|---|---|---|
| ① 提示词适配 | 不改权重，用 system prompt、few-shot、输出模板约束行为 | 几乎为零，小时级 | 输出格式、语气、角色、简单任务——**首选** |
| ② LoRA 轻量微调 | 冻结主干，只训练低秩适配器，得到小体积增量权重 | 中，需 GPU 和数据集 | 需要模型掌握特定知识、风格、术语 |
| ③ 蒸馏 | 用大模型输出当"教师信号"，训练小模型模仿 | 高，需数据与算力 | 要把大模型能力压缩到端侧小模型 |

**决策顺序**：先试提示词适配——绝大多数"模型不听话"其实是提示词问题，不值得动权重。提示词到极限仍不够，再上 LoRA。只有当需要把大模型能力整体迁移到小模型时，才考虑蒸馏。

LoRA 的合规前提同样是**数据许可**：用于微调的数据必须你有权使用，且训练产物不得违反底座模型的许可条款。

## 六、非官方模型预训练的合规前提

"预训练/微调一个非官方模型"不是想做就做，前提是**数据和许可都干净**：

- **只用有明确授权的数据**：训练语料必须有清晰来源与许可（自有数据、明确允许商用的公开数据集、或已获授权的数据）。不碰来源不明、爬虫抓取未授权、含个人信息的数据。
- **尊重底座许可**：微调产出的模型受底座模型许可约束。底座是 NC/研究许可的，微调产物同样不能商用。
- **核对衍生条款**：部分许可要求衍生模型改名、标注来源或同许可开源，发布前逐条核对。
- **保留追溯记录**：登记每个孵化模型的来源仓库、许可、基线更新时间、改造方式，便于日后审计。

一句话原则：**许可不清不孵化，数据不清不训练**。宁可放弃一个候选，也不给项目埋合规雷。

## 七、配套工具

候选检索与体检由 `scripts/model_scout.py` 完成，只用公开只读 API、免费无 Key（部分网络环境不可达会明确报错）：

```bash
# 按关键词检索候选（按下载量排序，标注是否可商用）
python3 model_scout.py search "coder 7b" --limit 5

# 体检单个模型：许可/格式/更新时间/下载量
python3 model_scout.py check Qwen/Qwen3-7B-Instruct --json
```

`search` 输出每个候选的 `commercial_ok` 字段（是否允许商用）；`check` 输出 `license`、`has_gguf`、`has_safetensors`、`last_modified` 等体检指标，正好对应上面第三、四节的审查项。退出码 0=完成，1=网络或参数错误。联网失败时如实报告"网络不可达"，不要编造下载量或更新时间。
