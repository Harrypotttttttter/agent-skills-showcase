# 本地部署指南

这份文档解决一个问题：把一个免费开源模型真正跑在本机，并作为 OpenAI 兼容端点接入 WorkBuddy，从安装到验证给出可照做的完整步骤和排错清单。

## 一、整体流程一览

本地部署分四步，顺序不要颠倒：

```bash
curl -fsSL https://ollama.com/install.sh | sh   # 1.安装 Ollama（macOS 也可下 Ollama.app）
ollama pull qwen3.5:9b                          # 2.拉取权重（首轮下载，之后离线可用）
ollama run qwen3.5:9b '用一句话介绍你自己'      # 3.验证本地推理
curl -s http://localhost:11434/v1/models        # 4.探活 OpenAI 兼容端点
```

服务安装后默认监听 11434 端口。第 4 步返回 JSON 模型列表，就说明端点可被 WorkBuddy 直接接入：

```
http://localhost:11434/v1/chat/completions
```

## 二、量化级别：体积与质量的权衡

模型原始权重通常是 FP16（16 位浮点），体积巨大。"量化"就是把权重压成更低位数，用少量精度换大幅体积下降——这是消费级硬件能跑大模型的关键。Ollama 标签后缀就是量化级别。

| 量化级别 | 每权重位数 | 相对体积 | 质量损失 | 适用 |
|---|---|---|---|---|
| Q4_K_M | 4 位（K 块量化，中等） | 基准（最小可用档） | 轻微，日常几乎无感 | **默认推荐**，平衡体积与质量 |
| Q5_K_M | 5 位 | 约 +20% | 更小 | 内存有余、追求更高质量 |
| Q6_K | 6 位 | 约 +35% | 很小 | 接近原始质量，内存充足 |
| Q8_0 | 8 位 | 约 +90% | 极低 | 几乎无损，但体积接近翻倍 |
| FP16 | 16 位 | 约 2× | 无 | 一般本机不必，研究用途 |

选型目录里的体积数字（如 9B 6.6GB、4B 3.2GB）都是 **Q4 量化后** 的估计值。

**怎么权衡**：内存紧张或追求速度用 Q4_K_M（多数场景的甜点）；内存富余、做推理/长文等质量敏感任务升到 Q5/Q6。别盲目追高量化——Q4→Q8 体积翻倍但体感提升有限，不如把内存留给更大的模型。指定量化用 Ollama 标签：

```bash
ollama pull qwen3.5:9b-q5_k_m    # 指定 Q5_K_M
ollama pull qwen3.5:9b-q8_0      # 指定 Q8
```

## 三、硬件与模型对照表

按可用内存（物理内存 × 0.7 Mac / × 0.6 普通）选择规模：

| 可用内存 | 推荐规模 | 代表模型（Q4 体积） | 量化建议 |
|---|---|---|---|
| ≤ 5G | 0.6B - 4B | Qwen3.5 0.6B(0.5G)、4B(3.2G)、Gemma 4 E4B(3G) | Q4_K_M |
| 5 - 10G | 4B - 14B | Qwen3.5 9B(6.6G)、Phi-4 14B(8.5G)、DeepSeek-R1 8B(5G) | Q4_K_M，余量足可 Q5 |
| 10 - 17G | 9B - 27B | Qwen3.5 27B(17G)、Gemma 4 12B(7.6G) | 27B 用 Q4，12B 可 Q6 |
| 17G+ | 27B - 35B(MoE) | Qwen3.5 35B-A3B(24G)、GLM-4.7-Flash 30B(24G) | Q4_K_M |

加载规则：模型体积必须小于可用内存；否则 Ollama 会大量换页导致极慢，或直接加载失败。留出系统和其他程序的余量，别把内存吃满。

## 四、WorkBuddy models.json 接入细节

`models.json` 是一个**数组**，每个元素是一个模型条目。部署规划器会生成完整条目，你只需追加进去。

### 4.1 字段含义

| 字段 | 含义与填写 |
|---|---|
| `id` | 模型唯一标识，与选型目录 ID 一致，如 `qwen3.5-9b` |
| `name` | 显示名称 |
| `vendor` | 提供方标识，本地模型填 `LocalOllama` |
| `url` | OpenAI 兼容端点，本地固定 `http://localhost:11434/v1/chat/completions` |
| `apiKey` | 本地 Ollama 不校验，占位填 `ollama` 即可 |
| `supportsToolCall` | 是否支持工具调用，本地模型一般填 `true` |
| `supportsImages` | 是否支持图像输入，仅视觉模型填 `true`（如 9B/4B/27B、Gemma 4 系列） |
| `supportsReasoning` | 是否有推理/思维链能力（如 DeepSeek-R1、Phi-4、27B 填 `true`） |
| `useCustomProtocol` | 走 OpenAI 兼容协议，填 `false` |
| `description` | 说明文字，建议标注"免费开源、数据不出本机" |

### 4.2 追加与验证步骤

1. **先备份**（务必）：`cp ~/.workbuddy/models.json ~/.workbuddy/models.json.bak`
2. 打开 `~/.workbuddy/models.json`，确认顶层是数组 `[...]`。
3. 把生成的条目整条作为新元素追加进数组（注意与上一个元素之间加逗号，别破坏 JSON 结构）。
4. 校验 JSON 合法：`python3 -m json.tool ~/.workbuddy/models.json > /dev/null && echo OK`
5. 重启 WorkBuddy，在模型列表选择该条目，发一条消息验证能回复。

**铁律**：只生成配置、不擅自改动。改配置前先备份，改完先校验再重启。

## 五、常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 端口 11434 被占用 | 已有 Ollama 实例或其他程序占用 | `lsof -i :11434` 查占用；停掉旧实例或改 Ollama 监听端口 |
| 模型拉不动 / 卡住 | 网络问题、仓库不可达、磁盘空间不足 | 检查网络；`df -h` 看空间；重试 `ollama pull`；必要时换镜像源 |
| 显存/内存不足、加载失败 | 模型体积超过可用内存 | 换更小模型或更低量化（Q4→更小规模）；关掉占内存的程序 |
| 工具调用不支持 | 模型本身不带工具调用能力，或端点是纯对话 | 换支持 tool call 的模型；确认 `supportsToolCall` 填 `true` 且端点为 `/v1/chat/completions` |
| 端点返回 404 | 端点路径写错 | 确认为 `http://localhost:11434/v1/chat/completions`，先用 `/v1/models` 探活 |
| 回复很慢 | 模型偏大、纯 CPU 推理 | 换小模型/低量化；Mac 确认用上 Metal GPU 加速 |

## 六、配套工具

部署方案由 `scripts/deploy_plan.py` 生成，纯本地、零联网，只产出命令与配置、不自动执行：

```bash
# 生成 qwen3.5-9b 在 24G Mac 上的部署方案
python3 deploy_plan.py qwen3.5-9b --ram 24 --mac

# 生成 4B 在 8G 机器上的方案，输出 JSON
python3 deploy_plan.py qwen3.5-4b --ram 8 --json
```

输出包含四步部署命令（安装→拉取→验证→探活）、`workbuddy_models_json_entry`（可直接追加的 models.json 条目）、接入步骤清单和合规声明。模型 ID 可用 `select_model.py --list` 查询。退出码 0=生成方案，1=模型未知或参数错误。
